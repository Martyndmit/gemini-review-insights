# gemini-review-insights

PoC-проєкт до завдання 2 курсу «Хмарні обчислення» (КНУ імені Тараса Шевченка, ФКНК).

**Тема:** аналіз відгуків клієнтів за допомогою Gemini API: структуроване вилучення
тональності, аспектів і проблем.

Програма читає CSV з відгуками інтернет-магазину, надсилає їх у Gemini API порціями
та отримує для кожного відгуку JSON за заданою схемою (structured output):

| Поле | Що означає |
|---|---|
| `sentiment` | загальна тональність: positive / neutral / negative / mixed |
| `rating_estimate` | оцінка 1–5, яку автор найімовірніше поставив би |
| `aspects` | згадані аспекти (доставка, якість, ціна, підтримка, сайт, пакування, гарантія) з тональністю й цитатою-доказом |
| `issues` | конкретні проблеми, коротко українською |
| `needs_reply` | чи варто магазину відповісти |
| `summary_uk` | суть відгуку одним реченням |

Результат — таблиці CSV і HTML-звіт: розподіл тональності, аспекти з позитивними й
негативними згадками, черга відгуків, що потребують відповіді, точність порівняно з
ручною розміткою та словниковим методом, витрати токенів.

## Чому Gemini API

- **Безкоштовний рівень (free tier):** ключ в Google AI Studio видається без банківської
  картки; модель `gemini-3.8-flash` на ньому безкоштовна. Україна є в списку доступних країн.
- **Structured output:** `responseMimeType: application/json` + `responseJsonSchema` —
  модель повертає JSON, що відповідає схемі, тож не потрібно розбирати вільний текст.
- **Той самий код працює через Google Cloud** (Gemini Enterprise Agent Platform, до квітня 2026 —
  Vertex AI) — достатньо змінних середовища.

## Як це працює

```
reviews.csv ─► порції по 20 відгуків ─► generateContent (Gemini API)
                                          │  systemInstruction: правила аналізу
                                          │  responseJsonSchema: компактна схема
                                          ▼
                     JSON ─► перевірка Pydantic ─► повтор для пропущених відгуків
                                          ▼
              CSV + summary.json + report.html (+ порівняння зі словниковим методом)
```

- **Компактна схема:** у `responseJsonSchema` лише структура, типи й короткі `enum`
  (тональність, аспекти). Перша версія з описами полів, `minItems`/`maxItems` і діапазоном
  оцінки 1–5 була відхилена API: `400 INVALID_ARGUMENT … too many states for serving`.
  API будує зі схеми автомат обмежень, і саме ці конструкції роздувають його.
- **Перевірка на клієнті:** діапазон оцінки, відомі аспекти, пропуски й дублікати перевіряють
  моделі Pydantic (`review_insights/schema.py`), кожен відгук окремо: невалідний відгук іде
  на повтор, решта порції зараховується.
- **Запасний режим:** якщо API все одно відхилить схему, програма повторює ту саму порцію
  в JSON-режимі (лише `responseMimeType: application/json`) і пише про це у звіті.
  Примусово — прапорець `--no-schema`.
- **Повтори:** помилки 429/5xx повторює SDK з експоненційною затримкою; якщо відповідь
  неповна чи обрізана, відгуки без результату надсилаються ще раз меншою порцією.
- **Ліміти free tier:** `--rpm` обмежує кількість запитів на хвилину (типово 10).
- **Захист від prompt injection:** текст відгуків передається як JSON-дані, а системна
  інструкція забороняє виконувати інструкції з відгуків (див. відгук `r13` у демонаборі).

## Встановлення

Потрібен Python 3.11+ (вимога SDK `google-genai`).

```bash
git clone https://github.com/<your-login>/gemini-review-insights.git
cd gemini-review-insights
python -m venv .venv
source .venv/bin/activate          # Linux / macOS
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Ключ API

1. Відкрийте https://aistudio.google.com/apikey і натисніть **Create API key**.
2. Скопіюйте `.env.example` у `.env` і впишіть ключ:

```
GEMINI_API_KEY=ваш_ключ
```

Файл `.env` є в `.gitignore` — не публікуйте ключ на GitHub.

**Через Google Cloud (Agent Platform, колишній Vertex AI) замість ключа:** увімкніть API в
проєкті GCP, виконайте `gcloud auth application-default login` і задайте

```
GOOGLE_GENAI_USE_VERTEXAI=true
GOOGLE_CLOUD_PROJECT=<PROJECT_ID>
GOOGLE_CLOUD_LOCATION=global
```

(або інший регіон, де доступна обрана модель). Змінна називається `..._VERTEXAI` за
старою назвою сервісу — так її читає SDK.

## Запуск

```bash
# 1. Перевірка конвеєра без ключа (словниковий метод, без API)
python -m review_insights analyze data/reviews_demo.csv --offline -o results/offline

# 2. Скільки вхідних токенів займе аналіз (метод countTokens, безкоштовний)
python -m review_insights estimate data/reviews_demo.csv

# 3. Аналіз через Gemini API
python -m review_insights analyze data/reviews_demo.csv -o results/gemini
```

Параметри `analyze`:

| Параметр | Типово | Опис |
|---|---|---|
| `--model` | `gemini-3.8-flash` | модель Gemini |
| `--chunk-size` | 20 | відгуків в одному запиті |
| `--thinking` | `low` | рівень міркувань: low / medium / high |
| `--rpm` | 10 | максимум запитів на хвилину, 0 — без обмеження |
| `--limit` | — | взяти лише перші N відгуків |
| `--no-schema` | — | JSON-режим без схеми (перевірка однаково через Pydantic) |
| `--offline` | — | без API, словниковий метод |

Свої дані: CSV з колонками `id` і `text`; колонка `sentiment_gold`
(positive / neutral / negative / mixed) необов'язкова — якщо вона є, звіт рахує точність.

## Результати запуску

У теці `-o` з'являються:

| Файл | Вміст |
|---|---|
| `report.html` | аналітичний звіт, відкривається в браузері |
| `reviews_enriched.csv` | відгуки з усіма полями аналізу (відкривається в Excel) |
| `aspects_long.csv` | згадки аспектів у «довгому» форматі для BI-інструментів |
| `summary.json` | агрегати, метрики якості, токени й вартість |
| `raw_responses.jsonl` | сирі відповіді моделі для перевірки |

## Демонабір

`data/reviews_demo.csv` — 40 відгуків вигаданого інтернет-магазину електроніки,
складених вручну для демонстрації (не реальні клієнти). Є складні випадки: сарказм
(`r04`, `r31`), заперечення (`r16`, `r33`), змішані відгуки, запитання, англійська мова
і спроба prompt injection (`r13`). Колонка `sentiment_gold` — ручна розмітка тональності.

Словниковий метод (`review_insights/baseline.py`) складено із загальних оцінних слів без
підгонки під демонабір. На ньому точність тональності — 68 % (macro-F1 0,65):
він не бачить сарказму й заперечень.

## Тести

```bash
pip install pytest
pytest -q
```

Тести проходять через справжній клієнт `google-genai`, але HTTP-відповіді імітуються
(`httpx.MockTransport`), тож ключ і мережа не потрібні. Перевіряються URL і заголовки
запиту, компактність схеми в `generationConfig`, перехід у JSON-режим після відмови API
прийняти схему, повтор лише невалідного відгуку, повтор пропущених відгуків, повтор після
429, зупинка зі збереженням результатів після помилки 403, `countTokens`, читання `.env`
з BOM і побудова звіту (17 тестів).

## Обмеження й безпека

- На free tier запити можуть використовуватися для покращення продуктів Google — не
  надсилайте персональні дані клієнтів; знеособлюйте відгуки або переходьте на платний рівень.
- Ліміти free tier (RPM, RPD) залежать від проєкту; актуальні — в AI Studio
  (https://aistudio.google.com/rate-limit). При вичерпанні денного ліміту аналіз
  зупиняється, а вже отримані результати зберігаються у звіті.
- Ціни для оцінки вартості (`review_insights/pricing.py`) взято зі сторінки
  https://ai.google.dev/gemini-api/docs/pricing станом на 12.11.2026.

## Структура

```
review_insights/
  schema.py     Pydantic-моделі відповіді та JSON Schema для API
  prompt.py     системна інструкція та формування запиту
  analyzer.py   клієнт Gemini: порції, перевірка, повтори, облік токенів
  baseline.py   словниковий метод (точка порівняння й офлайн-режим)
  evaluate.py   точність, macro-F1, матриця помилок
  report.py     агрегація, CSV/JSON, HTML-звіт
  pricing.py    ціни та розрахунок вартості
  cli.py        командний рядок
data/reviews_demo.csv
tests/
```
